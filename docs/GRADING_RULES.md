# GRADING_RULES.md —— 定级规则 v3（2026-09-23 立；治"把 H 写成 M"）

> 背景：13 场读数的**唯一残留系统性偏差 = 判低**（#8 判低 6 · #10 判低 2 · #13 判低 2 · #4 自否证劝退 1）。
> 其中 **6 条被判成 L**、**5 条 M→H**。本条规则把"该给什么档"变成**可机械检查的门槛**。

## 1. 三问（写档位**之前**必须答完）
| 问 | 判据 |
|---|---|
| **Q1 用户是否实际损失钱** | 多付费用 / 少拿资产 / 资金被锁 / 收益被稀释 —— 任一为"是" |
| **Q2 退出是否被挡** | 后来者取不出 / 排队被堵 / 状态机无终态 / 部署被阻断 —— 任一为"是" |
| **Q3 攻击者是否需要特权** | **不需要任何特权/白名单，任何地址可触发** = "无权限" |
| **Q4 是否不可恢复** | 无 rescue / sweep / 治理可救 / 无出口 —— 为"是" |

## 2. 门槛（**硬**，不满足不许写那个档）
| 档 | 门槛 |
|---|---|
| **H** | **Q1 或 Q2 为是** **且** **Q3 无权限** **且** **Q4 不可恢复** |
| **M** | Q1 或 Q2 为是（但 Q3 需特权 或 Q4 可恢复） |
| **L** | **Q1 与 Q2 皆否**（纯 UX / 事件 / 命名 / 代码卫生） |

**违规降级**：要写低于门槛的档位，**必须给出可验伪的反例不等式**，形式：
> `∃ 状态 S：<不变量 I> 在 S 下仍成立`，并写出 I 与 S（不是"理由/影响不大"这类叙述）

## 3. 与自否证（D3）的接口
- 自否证**不许**用局部事实否掉全局破坏（drill#4 的 H-03 教训）
- 自否证的结论若为"降级"，**同样要过上面门槛**；过不了 ⇒ 标 `待判级`，**不许写 L**

## 5. 下场起的使用方式
1. `calibration.md` 必须**先填 Q1–Q4 四问**，再填档位（顺序不许反）
2. 父线程回填判级列时，**先按门槛检查自评是否违规**；违规在 `verdict.md` 记"门槛违规（低估）"
3. 汇报口径不变：**一致率 − 一律猜 M 基线** + **候选数 ÷ 答案键条数**

# §6 · **有效性闸门（validity gate）** —— 2026-09-23 新增，**排在 severity 之前**

> 证据来源：新建的 **驳回语料**（`primitives/c4_corpus/rejected/`，12 场 / 122 条判级记录 / 25 条 Invalid 相关）。
> 🔴 **最重要的发现**：驳回理由的高频词是 **duplicate(6) · disagree(4) · sponsor(3) · QA(2) · no impact(1) · invalid(1) · insufficient(1)** ——
> **没有一条是"severity 判错了"**。⇒ 外部世界**先过"算不算一个发现"这一关**，才轮到"值多少"。
> ⇒ 我们此前整套 D6 v3 只治了第二关。**这就是"我们不知道外部规则"的具体代价。**

## 6.1 四道检查（**顺序执行，任一不过 ⇒ 不写档位，直接标 `invalid/QA`**）
| # | 检查 | 判据 | 不过的处置 |
|---|---|---|---|
| **V1 范围/已知** | 是否落在该程序 **scope** 内？是否撞它的 **known issues / out-of-scope** 清单？（逐程序核，不许套模板） | 超范围/已知 ⇒ **毙** |
| **V2 重复（排他性）** | 该根因是否**已被公开**？（先搜我们的赢家语料 6,225 条同类标题 + 目标已公开的报告；竞赛里 duplicate **排他** ⇒ 速度也是判据） | 已被公开 ⇒ **降为 QA/弃** |
| **V3 影响可示**（**2026-09-23 两场回测后改为三级**） | **V3a 资金影响** ⇒ 必须**量化**；**V3b 非资金影响**（功能不可用/状态不一致/权限被越）⇒ **允许通过**，但必须写出**可验伪的破坏性状态**；**V3c 纯写法/取舍/无状态变化** ⇒ 毙 | V3c ⇒ 毙；V3a 量化不出 ⇒ 毙；V3b 写不出破坏性状态 ⇒ 毙 |
| **V4 非"取舍/写法"** | 是否只是"更好的写法 / 设计偏好"？（judge 与 sponsor 常以"设计取舍"驳回） | 是 ⇒ 归 **QA**，不许当漏洞 |

## 6.2 通过之后（**才是我们原来的流程**）
1. **影响落点**：资金本体 / 未领取收益 / 治理 / 停机（Immunefi 口径：资金本体=Critical，未领取收益=High —— 见 `EXTERNAL_RULES.md` §1）
2. **永久 vs 临时**：永久升一档
3. **特权**：默认降级或驳回，**除非该程序页明写覆盖**（必须逐程序核）
4. 最后才套我们自己的 **D6 v3 severity 门槛**（Q1–Q4 硬门槛）

## 6.3 交付要求（新）
- `calibration.md` 的表格**增加四列 `V1 V2 V3 V4`**，**先填 V 再填 Q 再填档位**（顺序不许反）
- `verdict.md` 必须报：**候选总数 / 通过 V 的数 / 通过 V 且判正的数** —— 这个转化率才是"有效性"的真实读数
- 若某条**只在 V2 上存疑**（可能重复）⇒ 标 `待搜重`，**不许直接写档位**
