# READING_METHOD.md —— **换读法**（2026-09-22 立；治"召回"，当前第一短板）

> 触发：11 场真靶 drill 后，**H recall 长期卡在 6–25%**（#7 16.7% / #9 18.2% / #10 25% / #11 5.9%），
> 候选池常只有 **12 条 vs 答案键 40–57 条**。结论：**卡点不在"敢不敢判"，在"读什么、按什么顺序读"**（drill#11 的自我诊断：召回不足 ≠ 对冲）。
> 本文把"读法"从"顺着文件逐行 + 看代码味道"改成 **数据排序的三轴 + 差分优先**。

| 预言机 / 价格 | 11.7% | 11.0% | +0.7pp | 中（量大，H/M 同形） |

（旧读法实际上是"顺着文件读 + 看 smell"，所以时间大量落在 DoS/奖励 上，**漏掉的正是 lift 最高的权限与数学**）

## 2. 交叉验证（我们自己的 11 场）
**drill#11 vader 漏掉的 H**：`H-13 Anyone Can Arbitrarily Mint Synthetic Assets` · `H-14 Anyone Can Arbitrarily Mint Fungible` · `H-21 mintFungible/mintSynth with other user's balance` · `H-26 All user assets approved to VaderPoolV2 may be stolen` · `H-24 Wrong design of addLiquidity allows steal` · `H-15/H-16 Router swap 算错`

⇒ **这是"读序错"的直接证据，不是"能力不行"。**

## 3. 换读法的三轴定义（每场必做，机械产物）
| 轴 | 做什么 | 产物 | 为什么（数据） |
|---|---|---|---|
| **A. 权限轴** | 列全部 external/public 入口 × 谁能调 × 实际校验（file:line）× 缺口 × 影响 | `perm_matrix.md`（drill#10 建，**升级为每场标准件**） | H-lift **+3.5pp**；vader 漏的 H 一半在这 |
| **B. 数学轴** | 列出每个**算式** + "它应该等于什么"（不变量/公式）+ 可验伪反例（不等式） | `math_audit.md`（新） | H-lift **+3.0pp**；+ 分叉改坏的地方必在这 |
| **C. 清算/抵押轴** | 谁在什么状态下被强平 / 拿不到抵押 / 状态机无终态 | `liq_audit.md`（新） | H-lift **+2.7pp** |

## 4. 差分优先（新机械件：`scripts/fork_lineage.sh`）
**观察**：绝大多数竞赛靶是已知协议的分叉（vader = **Uniswap V2 fork**，指纹实测命中 15 个 .sol；另有 synthetix-staking 血统）。
判级 H 多落在"**分叉改坏的地方**"。
**流程**：
1. `bash scripts/fork_lineage.sh <靶码目录>` → 谱系指纹表 + "被改写过的关键函数"排行
2. 取**上游参考实现**（同一份 fetch 通道）
3. 对同族函数逐对 diff（`sibling_diff.sh` / 人工）⇒ **优先看两类差异**：
   - **上游有、这里没有的检查**（权限/边界/滑点）⇒ 归 A 轴
   - **上游没有、这里改动的算式** ⇒ 归 B 轴
4. 只在与上游不同的区域上做逐行精读（把逐行读的时间花在"改过的地方"）

## 5. 与旧闸门的关系（不冲突）
旧闸门（G0 / 层定位 / 覆盖 ≥70% / 四问 / D1–D6 / E4 取源）**全部保留**；本文只改**读什么、按什么顺序读**：
> **覆盖率的分子权重应偏向三轴与差分区域** —— 不是"每个文件都逐行"就叫读过了。

## 6. 首验与验收
- **首验（下一场 drill）**：按新读序（A→B→C→差分）+ 三件产物跑一场，对比上一场的 **H recall**（#11 = 5.9%）
- **验收**：`perm_matrix.md` / `math_audit.md` / `liq_audit.md` 三件齐 + `fork_lineage.sh` 跑过 + **H recall 提升**（目标 >25%）
- 若 H recall 仍不升 ⇒ 说明卡点不在读序，回到"判正/可达性"继续查（并如实记录）
