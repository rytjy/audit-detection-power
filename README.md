# Audit Detection Power — 我们自己量出来的盲测漏检率

一个简单的问题，公开答案几乎没有：**一个智能合约审计流程，在真实竞赛里实际抓到了多少官方认定的 H/M，又漏了多少？**

这个仓库把 5 场 Code4rena 盲测（2025-07-lido / 2025-10-hybra / 2025-10-sequence / 2025-11-megapot / 2025-11-merkl）的原始记录、冻结清单和合并统计放在一起。

## 结论（先看这个）

| 指标 | 值 | 95% CI (Wilson) |
|---|---|---|
| 严格命中 | **5 / 30 = 16.7%** | 7.3% – 33.6% |
| 含部分命中 | 10 / 30 = 33.3% | 19.2% – 51.2% |
| 漏掉 | **25 / 30 = 83.3%** | — |

- 分母为 0 的场次（lido，官方 H+M = 0）**不进合并**。
- 覆盖 100%、仍然漏 83.3%。已逐条归因的 17 条漏里，**16 条是「读过但没连起来 / 判成非问题」**，只有 1 条是缺判据。
- 另有 1 条不是漏，是**自己把命中的降级扔掉了**（merkl M-02）。

⇒ 瓶颈不在覆盖率，在**判据与定级**。

## 诚实限制（别跳过）

1. **4 场是 OFF 臂**（判据清单关闭）。唯一一次 ON 臂（sequence 5/6）的判据是从该场官方条目反推的，**半循环，不可引用为能力**。
2. sequence 报告指定的唯一有效检验——「把判据带到全新未污染靶上重跑」——**至今未做**。判据已定：新靶严格 ≥50%（≥3/6）且 1−精确率 ≤40%。
3. 时间盒 7–60 分钟净读，远小于竞赛的 10 天窗口；读者每场都是全新隔离线程。
4. 「1−精确率」的分母是**我们自己的提交阈值**，不是 TN 全域 ⇒ **不是 FPR**。
5. 官方 QA 未逐条公开 ⇒ 该指标只能是上界。

## 目录

- `bench/BENCH_DETECTION_POWER.md` — 合并表、口径定义、漏因分布（**主文件**）
- `bench/BENCHMARK_*.md` — 逐场报告：分母出处、盲测纪律时间戳、逐条命中/漏/假阳性、归因
- `bench/BLIND_LIST_*.md` — 读官方报告**之前**落盘的候选清单（盲测证据）
- `bench/blind-*/` — 冻结产物（CANDIDATES / FREEZE / official_report 快照）
- `docs/` — 判据模板、阅读方法、评分规则、预注册模板
- `scripts/sloc.sh` — 统一行数口径（唯一口径，避免与官方 nSLOC 混用）

## 怎么复核

1. 打开 `bench/BENCHMARK_<靶>.md` 的 §0/§1，核对清单 mtime 与官方材料抓取时间（间隔 20–66 秒）。
2. 分母取自官方报告原文，链接在该文件内。
3. 合并数在 `bench/BENCH_DETECTION_POWER.md` §2；CI 用 Wilson，n 为官方条目数（注意：不是独立试验次数）。

## 这不是什么

- 不是「我们的准确率」——是**这批靶上的历史战绩**。
- 不是漏洞赏金成绩单：这些场次没有提交过，只做盲测自评。
- 不是方法论推广：唯一一次 ON 臂实验是半循环的，方法本身尚未被验证。
